# LLM 当评委为什么总打高分

> **一句话**：用 LLM 给内容打分，结果全 5 分、满分——别高兴，这是评分失效的信号，不是你的内容真的好。

## 问题

写了个内容评分脚本，用本地 LLM（qwen3:8b）当裁判，四维打分。跑第一篇 TIL，结果 **625/625 满分**，四维全 5 分。第一反应是"写得好"，第二反应是"不对劲"——每篇都满分，评分还有什么意义？

## 根因

LLM 当评委（LLM-as-Judge）有个通病：**评分偏松，倾向给高分**。原因包括：
- 训练数据里"好评"远多于"差评"，模型学会了"讨好"
- 缺少明确的分差锚点，模型默认往高打
- 单篇孤立评分，没有横向对比，失去参照

## 解法：三个校准手段

| 手段 | 做法 |
|------|------|
| 加评分锚点 | rubric 里写死：5=极罕见 / 4=优秀 / 3=合格 / 2=有明显问题 / 1=很差 |
| 横向对比 | 多篇一起评，逼它排出相对高低，而不是每篇绝对满分 |
| 降低温度 | 降低采样温度，减少"讨好式"的随机高分 |

## 反直觉判断（真正的踩坑点）

1. **满分是警报不是喜讯**——区分度消失 = 评分系统失效
2. **LLM 会"迎合"你**——它知道你期待好评，就会给你想看的分数
3. **评分锚点比评分模型更重要**——换个更贵的模型，不如先把 rubric 的锚点写清楚

## 通用迁移

> 任何"让 AI 做裁判/评估"的场景，先假设它会偏松，主动加锚点 + 横向对比 + 人工抽检。AI 适合做初筛，不适合做最终裁决。
