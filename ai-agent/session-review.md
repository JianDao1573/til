# 让 AI 每天自动沉淀

> **一句话**：每天做了很多、也踩了很多坑，但下次照样重踩——因为"沉淀"靠手动，而手动必然遗忘。让 AI 定时自动复盘，才闭环。

## 问题

和 AI 协作一整天，解决了不少问题、踩了不少坑。但第二天再来，AI 还是不知道昨天学到了什么——踩过的坑照样踩，因为没人把经验"沉淀"下来。

## 根因

沉淀是"重要但不紧急"的事，永远排在当下任务的后面。手动写总结，坚持不了三天。核心矛盾：**沉淀的价值在"未来复用"，但动力只在"当下"——靠自觉必断。**

## 解法：四层提炼 + cron 自动复盘

| 层 | 提炼什么 | 写到哪 |
|----|---------|--------|
| A 事实 | 业务事实（公司/人员/产品） | Obsidian 卡片 |
| B 方法论 | 踩坑/反直觉/可复用工作流 | 技能 skill |
| C 工具 | 脚本缺步骤/命令错/OS 坑 | 技能 patch |
| D 纠偏 | 用户纠正/铁律/偏好 | memory |

配一个 cron（每天 18:30），让 AI 扫当天会话 → 四层提炼 → 自动写入。**沉淀从"记得做"变成"定时自动做"。**

## 反直觉判断（真正的踩坑点）

1. **沉淀不是"写总结"，是"判断什么值得记"**——判据只有一条："这条知识，未来同类任务能不能少踩一次坑？"能就记，不能就丢
2. **软规则和硬规则要分流**——偏好/铁律写 memory（AI 自觉），可执行规则写 config/脚本（工具强制），别混
3. **自动化本身就是沉淀的兜底**——与其提醒自己"记得复盘"，不如让 cron 定时触发

## 通用迁移

> 任何"重要但不紧急、靠自觉才能坚持"的事，都可以套这个公式：**提炼框架 + 判断标准 + 定时自动化**。让机器替你记住"该做了"。
