# 让 AI 遵守规则：声明规则 + 工具执行 + 校验兜底

> **一句话**：AI 反复犯同类错误时，别靠"提醒它"，靠"规则引擎 + 校验器 + 定时任务"。

## 问题

用 AI Agent（或任何自动化程序）管理文件时，它经常不守规矩：
- 文件放到错误目录
- 过期文件不归档
- 规则明明写在文档里，每次会话却"遗忘"或"绕过"

## 根因：方向错了

直觉解法是"让 AI 更听话"——写更详细的规则文档、反复提醒。**这是错的。**

AI Agent 每次会话独立、会遗忘、会绕过规则。规则遵守一旦依赖"执行者的自觉"，就必然反复失败。

## 解法：四件套

| # | 动作 | 载体 | 例子 |
|---|------|------|------|
| 1 | **规则声明化** | config/json | `sort_rules.json`（文件名→目录） |
| 2 | **正向执行** | 工具 | organize 规则引擎自动归档 |
| 3 | **反向校验** | 审计脚本 | 扫描"错位文件"，只读不写 |
| 4 | **定时自动化** | cron | 每天 07:30 归档 / 08:00 审计 |

## 案例：文件治理落地

```
规则声明（机器可读，非文档约定）
   ├─ sort_rules.json      → 分拣规则（文件名 → 目录）
   └─ organize-config.yaml → 归档规则（>7天 → 历史/）
        ↓
正向执行：organize（>7天的库存快照自动移到 历史/）
        ↓
反向校验：audit_structure.py（扫描散落/错位文件，有违规才报告）
        ↓
定时：cron 每天跑，零 token
```

## 三个反直觉判断（真正的踩坑点）

1. **"乱放"的根因往往是规则声明有 bug**，不是执行者故意乱放——先查规则，别骂执行者
2. **"过期"要先定义清楚**——这个场景里是"被新版本替代"（库存快照每天一份），不是"30 天没动"
3. **分拣规则 ≠ 审计规则**——正向分拣关键词可以宽泛，反向审计必须高置信度，否则误报淹没真问题

## 通用迁移

凡是 AI/程序反复犯的同类错误，套这个公式：

> **声明规则 + 工具执行 + 校验兜底 + 定时自动化**

这与你熟知的"管理学靠 SOP 不靠自觉"是同构的——你早就懂这个道理，只是第一次用在 AI 身上。
